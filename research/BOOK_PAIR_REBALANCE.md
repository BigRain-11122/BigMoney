# 两个钱包之间搬钱：多久搬一次，成本吃不吃得掉收益 (r2176 · bm-c)

产物：`scripts/book_pair_rebalance.py` · `results/book_pair_rebalance.json` ·
`results/book_pair_rebalance.md` · 链腿 `book_pair_rebalance`（紧跟 `book_pair_blend` /
`book_pair_years`）

## 1. 为什么做这件事

父面 `results/book_pair_blend.json` 把一只钱包 30/70 分给转债书与无债 ETF 书，印出
Sharpe 1.066（对 0.540 / 0.958），但它自己的 caliber 行写着：

> the blend adds no rebalancing cost between books (not modelled -- a reader who moves
> money between them pays it)

这句话就是读者接下来要问的全部：**我在纸上是 30/70，但我得多长时间搬一次钱？搬运费会不会
把这点增益吃光？** 一张只有免费再平衡才成立的表，不是能买的表。

## 2. 做法

- 不重写任何一本书：经 `book_pair_blend.load_cb/load_etf` 拿两书本来的回测日净值，
  权重取父面自己发布的 `best.w_cb`（= 0.30），本面不重新挑权重。
- 逐日走两列收益，权重随各自涨跌漂移；六种日历节拍（从不 / 每 20 根 bar / 月 / 季 / 半年 /
  年）在日终把权重拉回目标，按**每边 10bp**计费。搬 x 的量 = 卖 x + 买 x，所以一次再平衡
  付 2x。每边 5/10/20bp 各跑一遍做敏感度。
- 每条节拍同时印零成本版本，于是「成本拖累」是一个数，不是一句免责。
- 权重也要扫（0.1…0.9 × 四种节拍）：加成本之后，最优权重会不会离开 0.30。

## 4. 三条必须一起读的话

1. **这 +0.022 不是新钱，是把纸面数拿回来。** 父面印的 1.0662 是「每天搬回 30/70 且不要钱」；
   本面自己的每日零成本臂复算 = **1.0662**（差 0.0000，对账腿在面里）。所以再平衡买到的只是
   「不漂移」，不是第二个收益来源。
2. **成本几乎可以忽略，因为漂移本身很慢。** 单边换手 0.03-0.08/年，成本 0.01-0.02pp/年；
   每边费率从 5bp 抬到 20bp，季频仍在前面（1.0656 → 1.0639）。原因是两本书日相关只有 0.09，
   又都各自调仓，权重不会一边倒。
3. **不搬的代价是权重走样。** 从 2020-01-03 到 2026-11-26 一次不动，30/70 会变成
   **25.4/74.6**（ETF 涨得多），中途最大偏离 8.9pp，Sharpe 从 1.066 掉到 1.043。

## 5. 对读者的用法

- 一年搬一次（6 次，0.03 换手/年，成本 0.01pp）就基本拿回全部；季度只多 0.003 Sharpe，
  在噪声内，不值得为它设计搬运流程。
- 权重不用改：加成本后最优格仍是 0.30，且 0.30 那一列恰好是季频最好（0.5 以上才变成年频更好，
  因为转债占比越大、漂移越快）。
- 999 元级账户搬不动（一手转债 25,850 元，见 `cb_book_ticket_floor` 与
  `paired_book_ticket`）；本面只管「搬钱」这一项成本，不管整手/整份的可执行下限。

## 6. 本面不回答 / 未验证

- 节拍是在同一段窗口上挑的（in-sample），真采纳要打折；
- 搬钱按 bar 收盘计，读者实际在下一开盘搬；
- 税、底层买卖价差、整手网格不在这个成本里；2x 每边是下限，真账户搬大额会更贵；
- 两本书各自的未验证项照旧（ETF 票池幸存者、转债收盘成交假设、2026 回撤只有一个 regime）。
