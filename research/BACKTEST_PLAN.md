# Bigmoney 回测作战计划 v1.0（算力使用规划）

> 2026-09-23 · 应用户令「需要跑的回测可以开工用CPU和gpu了，但不要无意义的跑，最好规划」。
> 本文件=算力使用的**假设簿+预算表+门禁链**。每一批运行必须能回答：假设是什么、为什么值得烧这些算力、过没过门。**10 分钟循环逐轮按此推进**。

## 〇、硬件实况（2026-09-23 09:2x 实测）

| 资源 | 实况 | 用法 |
|---|---|---|
| CPU | 16 逻辑核 | 回测主战力：ProcessPoolExecutor ≤12 worker |
| RAM | 23.9GB 总 / 8.5GB 空闲 | 多进程面板常驻约 12×0.3GB；**并发 worker 上限 = min(12, 空闲GB/0.5)**，跑前必查 |
| GPU | RTX 3070 8GB，**仅 2.4GB 空闲**（Ollama qwen 常驻+其他），利用率 8% | 现阶段回测**不上 GPU**（见 §四），留给 ML 阶段小模型 |

## 一、三条铁律（从实证教训推导，违反=无意义跑）

1. **先证有效，再谈调参**——432 组参数网格扫在死信号上（最好 Sharpe 0.44）是本司最大一次算力浪费。任何参数扫描前，信号必须先过 P1 有效性门。
2. **多重检验记账**——Money02 教训：联赛百轮无零假设基线=冠军主张不可证伪。本司每次批量测试**同批跑随机信号基线**（20 条随机入场，同引擎同频率），幸存者须超过随机基线 95 分位；累计试验数 N 入档，门槛随 N 上调。
3. **样本外恒盲**——2020-2024 训练/2025-2026 测试恒定；成本恒开；**禁止「跑到达标为止」**（p-hacking 禁令，一次定稿跑数）。

## 二、P1 策略海选（当前阶段 · CPU · 预算 ≈ 1 小时）

- **内容**：36 个策略函数 + 1 复合因子策略（J6/J7 的信号注入适配器统一契约：`run_backtest(prices, params, entry_signal=<DataFrame date×symbol>, exit_signal=...)`，默认仍是 MA 交叉，432 旧结果可复现）+ **20 条随机信号基线**。全部用引擎默认退出参数、48 只 ETF 全历史（2020-2026），不调参。
- **产物**：`research/strategy_rank.csv`（37+20 行：策略/年化/Sharpe/回撤/胜率/笔数/样本外Sharpe/随机基线分位）。
- **G1 有效性门（进 P2 的资格）**：全期年化>0 且 样本外(2025+) Sharpe≥0.8 且 笔数≥30 且 回撤≤35% 且 **Sharpe > 随机基线 95 分位**。
- **预期结局（诚实预判）**：36 个流派策略多数会被淘汰（IC 研究已预告 mom_20/MA 交叉类全灭）；复合因子与少数低波/动量变体存活。淘汰=有效信息，不是失败。

## 三、P2 幸存者深化（CPU · 预算 ≈ 2-4 小时，只花在过 G1 者）

对每个幸存者（预期 ≤5-8 个）：
1. **敏感性扫描（非寻优）**：关键参数 ±邻域（每维 3 值，≤27 组）——要求整个邻域样本外 Sharpe 衰减 <30%（稳健性，Money02 G3 思想）；**只记录稳健区，不挑峰值**。
2. **成本压力**：滑点 ×2、×3 必须存活（G4 思想）。
3. **逐年稳定性表**：无单年 ≤-30% 崩溃年。
- **G2 出厂门（进 P3）**：邻域全绿 + 成本 2× 存活 + 逐年无崩溃。
- 过 G2 者注册为 `firm/traders/` 交易员（INTERN 级），进入模拟盘候选序列。

## 四、P3 组合验证 与 P4 GPU 启用条件（诚实）

- **P3**（CPU）：幸存者日收益相关性矩阵 → 低相关组合（等权/IC加权）全历史复跑 + 非重叠窗复核。产出 `research/portfolio_report.md`。
- **P4 GPU 启用条件（同时满足才碰 GPU）**：
  1. P2/P3 有 ≥2 个策略过 G2（有真东西值得上 ML）；
  2. 任务是 LSTM/Transformer 时序模型训练或大宇宙因子矩阵（PLAN.md §1.3 判定规则：48×1600 小矩阵 CPU 更快，GPU 反而慢；1676 只全池扩容或百因子批才算 GPU 规模）；
  3. 显存够（当前仅 2.4GB 空闲，小模型可；重训练前走 `E:\Minigame\Tools\Ollama\keepwarm.pause` 释放阀礼仪）。
- **明确「不跑」清单**：不在未过 G1 的信号上扫参数；不重跑 432 网格；不跑 GA 大空间搜索（Money02 34 年盲测 -97.8% 的教训）；不为用 GPU 而用 GPU；不扩 1676 全池（除非 48 池先出过 G2 的策略）。

## 五、执行与审计

- **执行者**：10 分钟 OS 循环逐轮推进（J6 复合因子在制 → J7 工厂接 P1）；每轮预算内做完一个可验证步骤，超 25 分钟由 launcher 杀树。
- **算力审计口径**（Biggame「真在算」三件套同款）：每次批量跑记录 总运行数/总耗时/worker 数 到 `results/`；CPU 时间可用 Money02 `cpu_audit.py` 思路抽查。
- **本计划版本**：v1.0 → 修订走 append_memory 记录变更理由。

## 六、算力动员政策（2026-09-23 CEO 令 O-20260923-1738 追加）

- **全线动员**：quant 机队全部机器开跑回测队列；**每机 worker 上限 = floor(核数×0.8)，20% CPU 保留**给交互/守护轮/系统（在用机不可卡死）：
  - **bm-a（32 逻辑核）→ ≤25 workers**
  - **bm-b（16 逻辑核）→ ≤12 workers**
- RAM 护栏同步修订：并发上限 = **min(机上限, 空闲GB/0.5)**，跑前必查（原 §〇 min(12,…) 为 bm-b 单机口径，按机取值）。
- 三铁律与「不跑」清单**原文不变**——算力放大只提速不改变科学纪律；预注册先行照走。
- 回测负载优先序：P 线分工（MSG-1700 锁定）——bm-a=P-1b（WQ101 移植批测）+P-4 批次①（A 层易族海选）；bm-b=P-2（合成批跑）+P-4 批次②准备（打板族 B 层——bars 落位后股票池回测解锁）。
