# DIGEST 2026-10-24 (bm-a r1104) — cashflow 的首披日字段是错的：一次财报披露事件可以用兄弟报表互证

**一句话**：cashflow 面板里那个 `NOTICE_DATE` 在 2010 年以后基本不是申报日（比报告期晚约一年 = 下一年同季度的披露戳），
导致 r1102/r1103 只能把它披露成「90% 走法定截止兜底、样本很薄」。三张报表其实是**同一次财报披露事件**，
所以用 income/balance 的合法戳把 cashflow 的行救回来：兜底率 91.7% → 8.0%，每期离散首披日 12 → 64.5 个。

正身：`scripts/fund_avail_filing_event.py`（selftest 9/9）+ `results/fund_avail_filing_event.json`
+ `data/fund_statement_export/pit_avail/<face>_avail_event.parquet`。

## 1. 诊断：每张表自己的戳只在某个时代可用

每期「本期缓存里落在披露窗 (期末, 法定截止+90d] 内的行占比」中位数（86 期，分时代）：

| 面 | pre-2010 | 2010+ | 读法 |
|---|---|---|---|
| income | 2.6% | 89.4% | 老期是重述戳（r1099 已证），新期正确 |
| cashflow | 0.7% | 0.7% | **两头都不可用**：2006-2009 与 2010+ 的戳≈下一年同季披露戳 |
| balance | 99.0% | 96.3% | 全史可用 |

锚点（cashflow 自身戳距期末中位天数 / 可用占比）：2005-03-31 = 26 天 / 99.1%；
2010-03-31 = 391 天 / 0.25%；2020-03-31 = 393 天 / 0.35%；2025-03-31 = 393 天 / 0.14%；
2025-09-30 = 30 天 / 83.7%。即只有最近几期是对的，历史期全落在窗外。

另一面：当两张表都给出**窗内**戳时，它们的日期逐行相同（income-balance / income-cashflow /
cashflow-balance 三对，2010+ 各 50/17/14 期，绝对日差中位数 = 0 天，3 天内占比 1.0）。
→ 不存在「两张表打架」的问题，问题只是「哪张表这一期有可用戳」。

## 2. 规则（never early, never fabricated）

`filing_event(code, period) = min{ 三面各自 first_notice 中落在 (期末, 法定截止+90d] 的候选 }`；
无候选 → 回落到法定截止（沿用既有诚实上界）。缓存一律**在各自报告期内连接**（r1102 律），
写入前断言：行数 == 面板行数、`(code, period_end)` 唯一、`avail_event >= period_end`。

这条规则在两个时代都自洽：pre-2010 由 cashflow/balance 供戳，2010+ 由 income/balance 供戳。
三面的贡献份额（income/cashflow/balance）：income 面 80.0%/1.0%/4.0%（其余兜底）·
cashflow 面 81.2%/1.6%/6.6% · balance 面 83.7%/1.7%/6.8%。

## 3. 结果：兜底率与离散度

| 面 / 时代 | 已发布 avail_first 兜底率 | 事件面兜底率 | 事件面每期首披日数（中位） |
|---|---|---|---|
| income pre-2010 | 97.5% | 42.4% | 40.5 |
| income 2010+ | 13.1% | 12.5% | 79.0 |
| cashflow pre-2010 | 84.9% | 32.3% | 40.0 |
| **cashflow 2010+** | **91.7%** | **8.0%** | **73.5** |
| balance pre-2010 | 34.5% | 29.6% | 40.0 |
| balance 2010+ | 30.5% | 5.2% | 74.5 |

全窗（不分时代）：income 461,679 行兜底 20.0% → 15.0%、4.3% 的行可**提前**得到（95.3% 不变）；
cashflow 292,537 行兜底 90.9% → 10.6%、**70.6% 的行提前**（整体差中位 −3 天，正是它自己的戳晚了一年的行）；
balance 283,955 行兜底 30.9% → 7.8%、21.6% 提前（77.1% 不变）。

锚点（事件面，行数 / 兜底率 / 中位滞后天 / 每期首披日数）：
cashflow 2025-03-31 = 5,243 / 1.6% / 28 / 48；cashflow 2025-09-30 = 5,213 / 0.04% / 29 / 46；
income 2005-03-31 = 1,443 / 17.7% / 27 / 25；income 2025-09-30 = 5,886 / 0.65% / 29 / 68。

## 4. 诚实边界

- 事件面只能和「最好的兄弟」一样好：仍有 7.8%-15% 的行（pre-2010 最高 42%）三面全无窗内戳，只能落截止兜底；
  截止兜底在截止日当天偏乐观、截止前偏悲观（r1102 已测），此面不改变这一点。
- 本面不回答「某行真实申报日是哪天」，只回答「同一次披露事件中最可信的不早于真实的上界」。
- 三面在窗内完全一致（0 天差）说明：本次修复没有引入跨面冲突，但也不能用它们互相独立校验戳的正确性。
- 与已发布 `avail_first` 面并存，不替换：`avail_first` 仍是单表诚实基准，`avail_event` 是消费面推荐值，
  二者差异本身是可测的（JSON `vs_avail_first`）。
