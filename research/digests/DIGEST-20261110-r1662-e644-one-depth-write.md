# DIGEST-20261110-r1662 — E644: 双层普查看不见的那一类写（一层深度的 store/delete）

**轮：** r1662 bm-b · **面：** `results/state_tilt/ONEDEPTHWRITE.json`

## 背景

E639 / E640 / E641 共享同一个人口：**同一 (行, 列) 挂着两个不同深度的 Subscript 站点**。这条生成规则本身自带盲区——`P['days'] = x` 只有一个深度，永远不产生"双深度"，所以这个共享人口里**不可能**存在它。而计数读行读的正是 `P['days'][...]`：同一个函数里如果整块替换 `P['days']`，读行依赖的那本映射就被整体重写，而三份面全都沉默。E644 就是这个盲区的定价。

## 方法

对 E640 面里那 6 个计数函数，取每个函数内**一层深度且 ctx 为 Store 或 Del** 的 Subscript 站点（普通赋值 / 增量赋值 / del），逐站点发布：

- 键：字面量拼写，或 `has_computed_key`（下标是表达式）；
- 容器：沿 `.value` 链折到根 Name，以及该 Name 在函数内的绑定（复用 E641 的解析器）；
- 与每个计数读行的 join：是否点名该行的键、位于读行**之前 / 同行 / 之后**。

同时把 E640 的双层写里"一层成员名就是计数键"的那一族（写进计数值**里面**，而不是整体替换）单独再读一遍。

## 结果

- 6 个计数函数里 **4 个**带一层深度写站点，共 **32 站点**（cn_core_ddctl_p1.run 18 / cn_mkneutral_p1.simulate 10 / e382_key_projection_delta.build 2 / e504_name_compose.selftest 2），ctx 全为 `store`（`del` **0**）。
- **0 个点名任何计数读行的键**（13 条计数读行，0 条受影响）。
- **0 个双层写索引进计数键**（写进计数值里面那一族也是空的）。
- **32/32 的容器都绑定在函数内部**（全为新本地容器；parameter 0 / module_scope 0 / unresolved 0）。
- **22 / 32 的下标是表达式**（`P[k]` 而非 `P['days']`），按定义匹配不上任何键——见教训 2。

判决 = 计数函数确实带一层深度写，但没有一个点名或索引进计数读行所读的键，**共享人口的盲区按测量是空的**（不是按假设）。

## 教训

1. **共享人口的定义里就藏着它的盲区。** 三个研究都在问"双层站点里……"，于是一层站点在它们全部射程之外。判"这个人口有没有漏掉一类写"，要先把**人口的生成规则本身**当对象问一次，而不是在同一人口里换问法。
2. **字面量匹配只能证字面量。** 32 个站点里 22 个下标是表达式，它们按定义匹配不上任何键；所以"0 个点名计数键"是关于**字面拼写**的结论。这个计数必须与判决同印，否则一个 computed 键在运行期正好等于计数键的情况会被读成已排除（种子 E645）。
3. **键名相等不是"写不写这本账"的答案**（承 E641）。本面把容器绑定一并发布：32 个写点即使写别的键，若穿过参数或模块作用域，仍可能落进调用方的映射。实测全为函数内新建，故"写侧是局部的"与"键不同名"两句话在同一批行上互相支持，而不是互为替代。

## How

凡"某个人口里的问法都答完了"，先把人口的生成规则找出来，问"按这条规则永远不会出现的形态是什么"——那才是剩下的盲区。再用最便宜的一次全量扫描把它定价，并把"能看见的部分"（literal）与"看不见的部分"（computed / 别名）**分别计数发布**，让判决与它的边界同时可读。
