## 问题

E528 看到的是一个函数的洞。这一轮问的是语料库层面的版本：**哪些函数带着计数器、把计数器拿去和一个常量比较、并从被选中的那一支返回空哨兵；这些东西的调用点又拿返回值做了什么。**

卡片明确要求把两类分开：**「上限是可发布出去的洞」**与**「上限在生产里根本到不了」**。

## 方法

- 人口 = `scripts/Tools/firm/live/monitor` 下**所有** `FunctionDef`（2,753 源，2,752 可解析，1 源语法不可解析并在 `sources_parsed` 里如实少 1）。
- 「空哨兵」只认 AST 上的字面量：`None / False / '' / () / [] / {} / set() / frozenset() / dict() / list() / tuple()`。经辅助函数算出的哨兵（`NULL = _null()`）不在射程内，且不会被发布成「没有」。
- 一支臂 = 单个 `Compare`（运算符 `< <= > >= == !=`）× 常量或符号上限 × 被选中支里**直接** `return` 空哨兵。
- **计数器的准入**（本轮最重要的一条）：一个名字被拿去比常量，**不等于**它是深度计数器。它必须满足二选一——①名字像计数器（`depth/level/lvl/ply/hop`），②它在同一个函数里被 `+1/-1` 送进**对自身的递归调用**。两者都不满足 = 索引/长度守卫，进 `rejected_counter_tests` 计数并给示例，**不静默丢弃**。
- 调用点归属：只有**同一模块**的调用，或**显式 import 了定义模块 stem** 的模块的调用，才有资格决定一条臂；其余同名调用计为 `unattributed_same_name_calls`，永不当读者。
- 调用点分类（对返回值做了什么）：丢弃 / 就地测试 / 绑定后测试 / 绑定后取下标 / 绑定后转发 / 绑定后返回 / 绑定后从不读 / 直接转发 / 直接返回 / 自递归。
- 「可分辨」的三档：**无测试就读**（`D_NO_TEST`）、**拿同一个空值去测**（`D_SAME_SENTINEL`）、**把空值当假值用**（`D_TRUTH`）；只有拿一个**非空值**去比较才算真的能看见上限（`D_DIFFERENT`）。

## 可复用教训

1. **拿常量比较的名字九成不是计数器。** 首版把任何「名字 vs 常量 → 返回空」都当深度臂，得到 88 条臂、其中 53 条被判「生产到不了」；两个数字都是伪影——`_sd(x, n)` 里的 `n` 是**长度**，`elig(prices, i)` 里的 `i` 是**bar 索引**。加上「名字得像计数器，或被 `+1` 送进自递归」的准入后，剩 12 条，同时 118 条被拒的测试被计进面里。这是 E207/E208「名即语义」族的第五现：**分类器换了门槛就必须公布它拒掉了多少、拒的是什么。**
2. **循环计数器不可能被判死。** 第一版把「没有递归 + 调用点字面量都小于上限」当死臂，于是 53 条「死」。但 `counter_is_assigned_inside_the_body_only` 的计数器由**函数体自己**往上加，任何调用都能把循环推到上限。死臂判据必须收紧成：计数器**只**由调用方供给、函数不递归、上限是 int、且每条调用路径（显式字面量，或省略时的字面默认值）都小于上限；任何一条路径的值不可知，臂就活着。
3. **同名调用会把一个臂的读者算成上千个。** 归属前 `main` 一条臂拿到 1,836 个「读者」——全是各模块自己的 `sys.exit(main())`。归属到「同模块或 import 了定义模块」后，这些调用一次也不落在别的模块的 `main` 臂上；562 个同名调用被单独发布。
4. **「死代码」这一档空了，本身也是读数。** 12 条臂全是递归的，递归总能走到自己的上限，所以这一轮不存在「生产到不了的上限」。把空档如实发布（0 条），比为了凑两类而放宽判据强——放宽就会重新把这些臂读成安全的。
