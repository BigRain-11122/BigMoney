## Why 18 of the 78 "openers" are not readers

E479 counted every `open` call whose path carries the twin's name, in any mode. Eleven of
those calls are the publishing instrument writing its own twin
(`e422` → basenamesensus, `e226` → breakeven, `e232` → costcurve, `e230` → hysteresis,
`e228` → matched, `e411` → readertiers, `e414` → replaycensus, `e252` → starown,
`e229` → timingsel, `e409` → unfloored), and seven are standalone doctor harnesses writing
the face on purpose and putting it back (dirfield, dirisface, republishchain, shadowface).

So for **10 of the 30 twins the label "opened only by a smoke or runner leg" is false**: the
script that publishes the twin is itself in the opener set. E479's own `producers` channel
names that source, so the two channels of the same face disagree — the residue class and the
producer evidence are not reconciled.

## The debt, priced in edits

The 57 read sites split 39 pin / 7 existence / 4 re-derive / 4 bytes / 1 presence /
2 no-field. Grouped by twin, 26 twins carry at least one pin, 3 carry a re-derivation,
1 only asserts presence — and **no twin's legs are all existence-only**. Deleting a twin
therefore never costs one guard deletion: all 30 owe an assertion rewrite that re-points the
reading at the producer's dated face (or drops the leg).

Re-derivation is rare (4 sites) and exactly where the leg imports the study's own builder:
`_tmp_r1275_smoke_leg.py` calls `e249_lead_counterfactual.derive_verdict` and compares with
the face's verdict; `e417_shadow_face.py` compares a stored face with a rebuilt one.

## Attribution: are E479's lines the right lines?

For each site the instrument re-folds the *live* path expression (unwrapping
`json.load(open(...))` to the innermost `open`, and following a bare name to its last
assignment above that line). 59 sites name what the parent recorded, **0 name a different
file**, 19 open a name this build cannot fold. One of the 19 is instructive:
`smoke_test.py:1857` opens a `data/futures_daily/*.csv` in a loop, yet the parent records
`replaycensus_latest.json` against that line — because `_p` is rebound by many legs in the
same file and the parent folds constants per file, not per leg. That is published as
unfoldable, not as an error: this build cannot prove the parent wrong there.

## Instrument corrections carried in the card

1. **"Reader" is a sub-question, not a premise.** A mode arm has to run before any reader
   census; otherwise a writer counts as a consumer and a retirement is mispriced.
2. **The unit is the asserting block, not the enclosing `with`.** All smoke legs live in one
   `main()`; function-level attribution and `with`-level attribution each mis-scaled the
   reading (41/57 and 49/57 re-derivations) before the asserting-block rule landed on 4.
3. **A re-derivation needs a builder on the other side.** `len(rows) < 5`,
   `os.path.join(...) in sys.path` and `json.dumps(seed) == "E398"` were all first-draft
   re-derivations, which inflated the retirement budget tenfold.
4. **Keep a class for "reads the file, asserts nothing".** Two shims and four byte-copy
   doctors are neither pins nor existence gates; folding them into either side would have
   priced the wrong edit.

## Limits

The population is E479's residue class, inherited: a reader E479 missed is not here either.
A site is classified by its asserting block, so a block asserting on two faces gives both
sites the same class. A call is read as a builder when it is defined in this file or in a
non-stdlib import; whether that builder actually rebuilds the face is not executable here.
Helper-parameter opens (3 sites) are named, not classified.
