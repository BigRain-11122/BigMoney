## 机制：首版三处误判

1. **人口取错**：按「print 里所有占位符」取，会把路径和耗时也算成计数（12 个里 6 个是噪声）。
   正法 = 在静态文本里只找 `{?}/{?}` 这一对，用斜杠定位分子与分母；这个对子是**数据**，写进面的
   `print_rule`，读者可反驳。
2. **兜底被自己的检索掐死**：dump 检索先被「路径里含 s6_chain」过滤掐空（bm-b 的路径在变量
   `out` 里），再叠加 `for _, name in RUNNERS` 的名字解包写反 —— 两个 bug 叠加的结果是 12/12
   全判成 `not_from_object`，**看上去像一个结论**。正法 = 取「print 之前最近一次 `json.dump`」，
   不看路径字面量；并把名字解包写对后用一条真读数做锚（bm-b 的 2 个字段必须是 payload）。
3. **「字段缺席」被算成「字段不符」**：2 份 bm-c 旧信封只有 `legs_total` 没有 `legs_rc0`，
   首版把它们的 rc0 计成不符。正法 = 缺席单列（`carrying_legs_rc0` 与 `differs` 两个计数器分开）。

## 教训

1. **「印出来的是不是从文件来的」必须有可证伪对照臂**：本轮把真源码里的 `payload["legs_total"]`
   换成 `312`（只改字符串副本，不动盘上文件），分类器必须把那一格改判 `a_literal_in_the_source`；
   如果那一句在源码里已经不存在，对照臂如实报 `applied=false`，**不许静默通过**。
2. 一旦 6/6 都来自载荷，剩下的错就只能是人口（`--only` / 早停），这把 E561 / E566 / E567 三张面
   收敛到同一个根因上：**句子的错不在算术，在它数的是哪一段**。
3. 三台 runner 的回执形状并不相同（信封带计数 / 裸列表 / 旧信封无计数），所以读者往往要重数才知道
   M —— 这正是「句子无法自证」的物理原因，也是为什么 E566/E567 必须去解析散文。
4. **回执目录是活的**：本轮自己的 S6 腿就会追加一份回执，`check` 因此对回执计数只门「增长」不门
   「恒等」（第一次跑就因为 `sources` 全等比较而假红）。

## 边界

纯静态 + 只读回执重数：不执行 runner、不改回执、不判句子对不对（那是 E567 的活）。bm-a / bm-c
当前 runner 不写计数字段这一事实只记录不修 —— 改 runner 不等于修句子，且会动三台共用的链。
