# 算力审计与防瞎跑白跑机制（v1.1 · 2026-09-24 升版 · CEO 令 O-20260923-1810 立法 + O-20260924-1626 判定即处置）

> 「你也要防止和检查cpu gpu瞎跑 白跑的情况。」三铁律与「不跑」清单（`research/BACKTEST_PLAN.md` §一）原文不变，本文件=**技术查账层**。
> v1.1（O-20260924-1626 R1/R2/R3）：判定与处置分离=根因——水位探针只记录、audit 只判不杀。本版起五旗=**判定+处置双列**，处置由 watchdog C7 腿（`Tools/watchdog.ps1`）机械化执行，红牌件 `results/watermark_red.json` 供 dashboard/轮报告实读。

## 一、定义（旗判定口径 + 处置动作）

| 旗 | 定义 | 阈值 | 处置（判定即执行 · O-1626） |
|---|---|---|---|
| 🚩瞎跑 | 高烧无产出：python 进程群占用高而 `results/` 无新产出 | python 聚合 CPU >60% 机器容量 **且** 最近结果件 mtime 龄 >15min | **杀**：C7 僵尸杀（白名单批模式+三查）留证（进程表+日志）；轮报告顶格 |
| 🚩白跑 | 有活不干：fleet 任务板有 open 件而机器空转 | open 任务 >0 **且** CPU 总载 <20% | **升级**：水位红牌件落盘 + 轮报告首行 P0 + GM 呈报面（GM 豁免权即时行使，禁闲置算力等门——O-1612 范式） |
| 🚩越限 | 超出 O-1738 算力上限 | CPU 总载 >85%（80% 上限+容差带）持续采样命中 | 下一批自动降档 worker |
| 🚩GPU 越权 | GPU 被碰而未过 P4 三条件 | GPU util >10% 且近 60min 无挂 P4 批号的 GPU 批注册 | **即杀**并轮报告 |
| 🚩僵尸 | 孤儿进程（round-8 教训：exit=0 但截断/超时未杀净） | python/pythonw 进程龄 >45min **且** 上轮 tick 至今 CPU 增量 <5s | **杀+续跑**：C7 三查保险（已知批模式白名单+交互会话守卫+杀落日志）→ checkpoint 续跑归既有自愈（S6 gates/C4/C5） |

## 二、审计器 `scripts/compute_audit.py`（每轮 S6 末尾自动跑）

- 采样：CPU 总载 / python 进程群 CPU（3s 差分窗）/ GPU（nvidia-smi 无则诚实 no_gpu）/ 最近批产出新鲜度 / fleet open 任务数。
- 输出：`results/compute_audit.json`（含历史采样，供趋势判定）；**异常才轮报告**（无旗=安静 exit 0）。
- 判定为「采样+历史」双源：单点尖峰不报（防误报），连续命中才立旗。
- 红牌判定与处置（R1 水位闭环）= `Tools/watchdog.ps1` C7 腿每 30min tick：尾 3 连续样本 py<70% 且存在可跑批（open 票/bandit）= 水位红牌 → 僵尸扫描杀+`results/watermark_red.json` 升级件；注入验收=`Tools/watchdog_c7_selftest.ps1`（真进程真杀 10 用例）。

## 三、批件纪律（硬性，账本前置检查）

1. 一切批跑必带：**预注册引用 + audit 段**（runs/elapsed/workers/cap 合规）——本司所有已交付批已合规，新批无 audit 段=审计不合格**不入试验账本**。
2. 同预注册同网格**禁止重跑**（p-hacking 红线的技术层）；数据批修复重跑须留痕声明（J9a 口径）。
3. 批开跑前查 RAM 护栏与 worker 上限（BACKTEST_PLAN §六）——越限即审计旗。

## 四、处置（v1.1：全部机械化，不再依赖人读人办）

- 瞎跑旗 → **杀进程留证**（进程表+日志），轮报告顶格记录；
- 白跑旗 → 水位红牌件 + 轮报告**首行 P0** + 总经理呈报面（队列喂批优先级顶格；GM 豁免权即时行使）；
- 越限旗 → 下一批自动降档 worker；
- GPU 越权 → 即杀并轮报告；
- 僵尸旗 → C7 三查后杀树 + checkpoint 续跑（续跑归各批既有自愈机制，C7 不重复代发）。

## 五、轮序与验证纪律（O-1626 R3/R4 新章）

- **R3**：轮会话 S3 执行顺序固定——**水位红牌 > 修红 > 其他一切**；每轮报告首行必含 watermark verdict（绿/红+原因一句话，读 `results/watermark_red.json`）。
- **R4**：GM 发任何资源/算力类令后，必须 30min 内回查一次执行水位（watermark/audit 实读），未生效即当轮处置；此后每 2h 抽查一次。适用于所有 GM 会话。
