# 算力审计与防瞎跑白跑机制（v1.0 · 2026-09-23 · CEO 令 O-20260923-1810）

> 「你也要防止和检查cpu gpu瞎跑 白跑的情况。」三铁律与「不跑」清单（`research/BACKTEST_PLAN.md` §一）原文不变，本文件=**技术查账层**。

## 一、定义（旗判定口径）

| 旗 | 定义 | 阈值 |
|---|---|---|
| 🚩瞎跑 | 高烧无产出：python 进程群占用高而 `results/` 无新产出 | python 聚合 CPU >60% 机器容量 **且** 最近结果件 mtime 龄 >15min |
| 🚩白跑 | 有活不干：fleet 任务板有 open 件而机器空转 | open 任务 >0 **且** CPU 总载 <20% |
| 🚩越限 | 超出 O-1738 算力上限 | CPU 总载 >85%（80% 上限+容差带）持续采样命中 |
| 🚩GPU 越权 | GPU 被碰而未过 P4 三条件 | GPU util >10% 且近 60min 无挂 P4 批号的 GPU 批注册 |
| 🚩僵尸 | 孤儿进程（round-8 教训：exit=0 但截断/超时未杀净） | python/pythonw 进程 CPU>0 且启动龄 >45min |

## 二、审计器 `scripts/compute_audit.py`（每轮 S6 末尾自动跑）

- 采样：CPU 总载 / python 进程群 CPU（3s 差分窗）/ GPU（nvidia-smi 无则诚实 no_gpu）/ 最近批产出新鲜度 / fleet open 任务数。
- 输出：`results/compute_audit.json`（含历史采样，供趋势判定）；**异常才轮报告**（无旗=安静 exit 0）。
- 判定为「采样+历史」双源：单点尖峰不报（防误报），连续命中才立旗。

## 三、批件纪律（硬性，账本前置检查）

1. 一切批跑必带：**预注册引用 + audit 段**（runs/elapsed/workers/cap 合规）——本司所有已交付批已合规，新批无 audit 段=审计不合格**不入试验账本**。
2. 同预注册同网格**禁止重跑**（p-hacking 红线的技术层）；数据批修复重跑须留痕声明（J9a 口径）。
3. 批开跑前查 RAM 护栏与 worker 上限（BACKTEST_PLAN §六）——越限即审计旗。

## 四、处置

- 瞎跑旗 → 杀进程留证（进程表+日志），轮报告顶格记录；
- 白跑旗 → 轮报告顶格呈总经理（队列喂批优先级顶格）；
- 越限旗 → 下一批自动降档 worker；
- GPU 越权 → 即杀并轮报告；
- 僵尸旗 → 按孤儿探针协议取证后杀树。

## 五、维护
