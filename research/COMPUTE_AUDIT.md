## 一、定义（旗判定口径 + 处置动作）

| 旗 | 定义 | 阈值 | 处置（判定即执行 · O-1626） |
|---|---|---|---|
| 🚩瞎跑 | 高烧无产出：python 进程群占用高而 `results/` 无新产出 | python 聚合 CPU >60% 机器容量 **且** 最近结果件 mtime 龄 >15min | **杀**：C7 僵尸杀（白名单批模式+三查）留证（进程表+日志）；轮报告顶格 |
| 🚩白跑 | 有活不干：fleet 任务板有 open 件而机器空转 | open 任务 >0 **且** CPU 总载 <20% | **升级**：水位红牌件落盘 + 轮报告首行 P0 + GM 呈报面（GM 豁免权即时行使，禁闲置算力等门——O-1612 范式） |
| 🚩越限 | 超出 O-1738 算力上限 | CPU 总载 >85%（80% 上限+容差带）持续采样命中 | 下一批自动降档 worker |
| 🚩GPU 越权 | GPU 被碰而未过 P4 三条件 | GPU util >10% 且近 60min 无挂 P4 批号的 GPU 批注册 | **即杀**并轮报告 |
| 🚩僵尸 | 孤儿进程（round-8 教训：exit=0 但截断/超时未杀净） | python/pythonw 进程龄 >45min **且** 上轮 tick 至今 CPU 增量 <5s | **杀+续跑**：C7 三查保险（已知批模式白名单+交互会话守卫+杀落日志）→ checkpoint 续跑归既有自愈（S6 gates/C4/C5） |
| 🚩单核占道（O-2130·第六旗） | 多核机器上算力批单核长烧：单 python 进程持续 ≈1 核（CPU 率≈1/核数） | >15min **且** 属算力批类（非 IO 拉数/单写者/LLM 轮·例外白名单登记制） | **杀+多核 runner 重排队**（checkpoint 续跑）＋强制多核化改造单；批入池必带 `workers_plan`（多核计划·O-2100 池 schema 字段） |
| 🚩池饿（O-20260925-1137·第七旗） | 池空机闲：可跑池 ready=0 而 python 群 py<70%（红牌条件的空池漏洞封堵） | 持续 ~30min（本采样+历史尾窗 ≥3 合格样本·跨度 ≥25min；历史样本无 `pool_ready_count` 键=不记账诚实不触发） | **供给真实批**（禁造数凑烧）＋轮报告首行点名＋供给协议 §八（研究线 prereg 供给节奏入法） |

## 二、审计器 `scripts/compute_audit.py`（每轮 S6 末尾自动跑）

- 采样：CPU 总载 / python 进程群 CPU（3s 差分窗）/ GPU（nvidia-smi 无则诚实 no_gpu）/ 最近批产出新鲜度 / fleet open 任务数。
- 输出：`results/compute_audit.json`（含历史采样，供趋势判定）；**异常才轮报告**（无旗=安静 exit 0）。
- 判定为「采样+历史」双源：单点尖峰不报（防误报），连续命中才立旗。
- 红牌判定与处置（R1 水位闭环）= `Tools/watchdog.ps1` C7 腿每 30min tick：尾 3 连续样本 py<70% 且存在可跑批（open 票/bandit）= 水位红牌 → 僵尸扫描杀+`results/watermark_red.json` 升级件；注入验收=`Tools/watchdog_c7_selftest.ps1`（真进程真杀 10 用例）。

## 三、批件纪律（硬性，账本前置检查）

1. 一切批跑必带：**预注册引用 + audit 段**（runs/elapsed/workers/cap 合规）——本司所有已交付批已合规，新批无 audit 段=审计不合格**不入试验账本**。
2. 同预注册同网格**禁止重跑**（p-hacking 红线的技术层）；数据批修复重跑须留痕声明（J9a 口径）。
3. 批开跑前查 RAM 护栏与 worker 上限（BACKTEST_PLAN §六）——越限即审计旗。

## 四、处置（v1.1：全部机械化，不再依赖人读人办）

- 瞎跑旗 → **杀进程留证**（进程表+日志），轮报告顶格记录；
- 白跑旗 → 水位红牌件 + 轮报告**首行 P0** + 总经理呈报面（队列喂批优先级顶格；GM 豁免权即时行使）；
- 越限旗 → 下一批自动降档 worker；
- GPU 越权 → 即杀并轮报告；
- 僵尸旗 → C7 三查后杀树 + checkpoint 续跑（续跑归各批既有自愈机制，C7 不重复代发）。

## 五、轮序与验证纪律（O-1626 R3/R4 新章）

- **R3**：轮会话 S3 执行顺序固定——**水位红牌 > 修红 > 其他一切**；每轮报告首行必含 watermark verdict（绿/红+原因一句话，读 `results/watermark_red.json`）。
- **R4**：GM 发任何资源/算力类令后，必须 30min 内回查一次执行水位（watermark/audit 实读），未生效即当轮处置；此后每 2h 抽查一次。适用于所有 GM 会话。

## 七、执行面分离与自动续批（v2.0 · O-20260924-2100 · CEO 直令）

**根因**：批启动耦合 10min 轮会话（轮串行·批间隙空转）＋票＝单机独占锁（认领机停滞＝整批冻结）＋发现≠填充（C7 只杀僵尸挂红牌、填活仍等轮）——纪律补丁治不了架构病。

| 件 | 机制 | 硬指标 |
|---|---|---|
| **Runnable Pool** | `results/runnable_pool.json`＝唯一算力待办面：ready 批（预注册冻结＋runner 在＋数据门绿）由轮写入池；bandit 队列并入 | ready 可见性＝commit 即全机可见 |
| **Auto-Fill** | `Tools/autofill.py`（watchdog **C8 腿**·10min tick·确定性零 LLM）：py<70% 且池非空→直接启动池顶批（BelowNormal·checkpoint 续跑·车道归属守卫 F-08·静默律·池单写者锁） | **入池→开跑 ≤10min** |
| **Shard Claims** | 票 schema 增 `shards` 数组（分片键/状态/owner/checkpoint/租约）；认领单位＝分片——多机多分片并行合法；票锁只锁科学面（预注册/判定） | CPU 批默认多机分片 |
| **Stale Takeover** | 分片 owner 心跳停滞 >20min → 分片自动回池（checkpoint 续跑），健康机即取 | 接管零 MSG 零人工 |
| **Inline Ban** | 轮内内联计算 >5min 一律入池提交后返回，轮只监控不代跑（bm-b 34min 挂轮＝反面教材） | 轮会话不再被长批劫持 |

合规：确定性脚本＋文件池＋分片协议＝机制约定非中央守护进程（cph4/scheduling 律）；同预注册同网格禁重跑律、三红线、GPU P4 律不变。验收判据＝O-2100 §四（T-36 注入验收）。

**v2.1 增补（O-20260924-2130 · CEO 直令「多核满用」）**：①ready 批入池注册**必带 `workers_plan` 多核计划**（ProcessPool·workers=min(核数−2, RAM 护栏)·BelowNormal）——单核长烧算力活＝违规、无多核计划不入池（`Tools/autofill.py` C8 读侧强制门）；②真串行活（网络 IO/单写者/LLM 轮）白名单登记制，不许拿例外当挡箭牌跑算力活；③audit **第六旗 `single_core_hog`**＝多核机上单 python 进程 ≈1 核持续 >15min 且属算力批类＝旗→杀+多核 runner 重排队（checkpoint 续跑）+多核化改造单（采样制＝候选+前采样≥10min 持续窗）；④在制单核构建（XSTOCK·O-1612 已令）今晚收口，后续大构建一律多核起跑。

## 八、第七旗「池饿」与供给协议（v2.2 · O-20260925-1137 · CEO 直令「全面利用好机器群的CPU算力 不要空置，该干满干满」）

**根因（审计漏洞）**：红牌条件=「有可跑批 且 py<70%」——池空（ready=0）时结构性绿灯：2026-09-25 11:04 实测 py 1.9% + 池 9/9 done = CLEAN 判定，CPU 空置却无旗。**池饿=供给面违令态**，本旗封堵该漏洞。

**判定（`scripts/compute_audit.py` 第七旗 `pool_starvation`）**：
- 样本态新增 `load_state` 三态分类：`burning-healthy`（py≥70%）/ `idle-starvation`（py<70% 且 ready=0）/ `pool-supply-gap`（py<70% 且 ready>0＝批在池未被烧＝C7 红牌既有面）；池件不可读=`unknown`（禁把 unknown 当 0 触发）。
- 旗条件=**ready=0 且 py<70% 持续 ~30min**（采样制：本采样+历史尾窗连续合格样本 ≥3 个且跨度 ≥25min；v2.2 前历史样本无 `pool_ready_count` 键=不可记账，诚实不触发首跑即红）；候选态 `pool_starvation_candidate` 单样本即记。
- 自检 `python scripts/compute_audit.py selftest`＝11 例 hermetic 场景（注入池饿序列必旗/满烧态零误报/池 fed 态不旗/历史 legacy 不冒进/跨短窗不旗/池不可读不旗/fed 样本断窗）。

**处置（供给面协议——旗=供给义务，非烧数许可）**：
1. 旗火 → 轮报告首行点名 + 水位升级面；处置=**供给真实批**（禁造任务凑烧·诚实律恒在）。
2. 供给检查序（机械可执行）：①在飞 claimed 票内扫「预注册已冻结+runner 已在」的批就绪规格 → 翻池 ready（带 workers_plan）；②外源波收口 → harness 批**立即**入池（禁规格囤在 claimed 态不排产）；③P1 新方向须署名单开工（O-1620 下放域）。
3. 判读边界：池饿旗火且板全闭环+bandit 空+无可跑批=O-1612 合法 idle 白名单证据面，轮报告如实标注（供给义务=「研究线 prereg 供给节奏入法」的整改面，非本窗可立即产出时空窗如实记）。

**CEO 面**：dashboard 事件流+`data.saturation` 面板（池 ready 数/本机 py 水位序列/池饿旗态，`monitor/build_status.py`）——每机 dashboard 显本机序列（watermark.jsonl 本机文件 gitignore 制设计，T-25）。
