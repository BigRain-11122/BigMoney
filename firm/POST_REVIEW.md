# 事后复审机制 POST REVIEW v1.0（O-20260924-2115 · CEO 直令正典）

> CEO 原话（2026-09-24）：「建立一个事后审查机制，确保你 AI 不是在自我感动和产生幻觉。」
> 集团法对接：FluxGroup `docs/governance.md` §10（诚实律三道防线/五诚实律/幻觉四分类）——本文件＝BigMoney 子司实施层＋**成果验证层**（集团法管宣称有没有证据；本机制管宣称的成果到底成没成）。

## 1. 核心原则：三分离

1. **动作与成果分离**：立法/建件/派工＝动作；只有**判据复验通过**＝成果。禁把动作报成成果（自我感动第一来源）。
2. **宣称与验证分离**：干活者不得自证成果——复审＝确定性脚本重derive＋跨机复核（执行侧不得自证＝集团法第二防线）。
3. **判据与叙事分离**：复审只对照**事前冻结的判据**，不对照执行者的事后叙事。

## 2. 机制四件

| 件 | 内容 | 节律 |
|---|---|---|
| **判据前置** | 一切令/票/机制批必带机器可验判据（文件存在/指标阈值/git 证据），事前冻结 | 落令时 |
| **确定性复审器** | `Tools/post_review.py`：对 24h 窗内已闭件重derive 判据→判 **✓达成／✗未达／🟡未到期**；零 LLM | 每日（watchdog **C9 腿**） |
| **跨机复核** | 复审器判 ✗/存疑的行→轮值机（**非执行机**）LLM 复核，裁决入台账；执行机申诉＝GM 裁定 | 触发式 |
| **宣称-复审对照面** | 复审台账 `results/post_review.jsonl`＋周聚合；战报/战绩页每行带复审列（宣称→复验＋证据指针） | 每周入周报＋月度四件套 |

## 3. 自我感动专项检测（复审器内置）

1. **动作词冒充成果词**：「已立/已建/已完成/已交付/已生效」出现处必须同格带判据复验指针，缺＝flag；
2. **报喜不报忧率**：正宣称/诚实负披露比——全正流本身即嫌疑（健康样本＝2026-09-24 之 6/6 FAIL、0/22 晋升如实入报）；
3. **预测-结果偏差**：事前判据预测 vs 实际结果的系统性偏乐观＝flag；
4. **宣称分级执法**：✓＝全过且当场重跑／🟡＝部分／⬜＝未动／✗＝失败（集团法口径），报告禁 ✓掩 🟡。

## 4. GM 自缚条款

- GM 向 CEO 汇报一律三态标注：**立法（git 可验）／生效（判据通过）／验收（复审 ✓）**——禁三态混报；
- GM 的令与战报同受复审器扫描（自我例外＝机制自杀）。
