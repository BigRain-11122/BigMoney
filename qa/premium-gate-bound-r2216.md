# r2216 — 执行闸从点估计变成区间（溢价面）

## 一句话

溢价面的「执行闸」过去只按金额说事：可核对腿合计多付 X 元，X 小于阈值就印「不提示」。
可那笔 X 里，有的腿的分母日期只是**标签**（r2215 已证：价格路径判不了日，两个日子的读数都自洽）。
本轮让闸带上那个不确定度：一条标签腿最多按它自己当日价动作偏，闸只在**连最坏情况也在阈值内**时才说「不提示」。

## 判词四态（`over_hurdle.verdict`）

| verdict | 条件 | 页面说什么 |
|---|---|---|
| `breached` | 点估计 > 阈值 | 原样（**执行闸：…> 阈值…**）；另有未证腿时加一行「未计入上面的数字，结论不依赖它们」 |
| `clean` | 无未证腿，点估计 ≤ 阈值 | 「不提示」（与原行为一致） |
| `clean-even-worst-case` | 有未证腿，点估计+不确定度 ≤ 阈值 | 「按各自当日价动最多再偏 W 元——把最坏情况算进来仍低于阈值，不提示」 |
| `unproven` | 有未证腿且最坏情况越过阈值（或不确定度连上限都算不出） | 「省不省到线，取决于一个本面没有证明的日期」/「『没超线』是一个没有证明的结论」 |

字段：`unproven[]`（symbol / date_proof / move_pct / amount_cny / exposure_cny）、
`exposure_cny`（无未证腿=null，不是 0）、`bounded_total_cny`、`verdict`。
`breached` 布尔与 `total_over_nav_cny` 语义不变（下游 `etf_premium_session_delta` 零改动）。

## 不确定度怎么算

一条标签腿 = 定日面判不了日的那条腿，判不了日的原因正是「该标的当日价动小于定日阈值」。
所以同一段价动就是两个候选净值的最大差：`exposure_cny = |move_pct| × amount_cny / 100`。
这是**上界不是分布**，页面上的 `basis` 字段原样写明。

## 盘上实读（2026-11-27 场）

改前：
```
执行闸：可核对腿合计多付 -1,184 元，未超阈值 500 元，不提示。
```
改后：
```
执行闸：可核对腿合计多付 -1,184 元；另有 2 腿（513690、159519）的分母日期只能算标签，
按各自当日价动最多再偏 883 元——把最坏情况算进来 -301 元，仍低于阈值 500 元，不提示。
```
含义：这张票面本来是**贴水**（-1,184），即使那两腿的日期真错了，最坏也只是 -301，仍是贴水——所以「不提示」这个结论本轮**经得起**。
若换一张贴水只有 100 元的票面，同样的 883 元不确定度就会把它翻成 `unproven`，页面会明说省不省到线取决于一个没证明的日期。
