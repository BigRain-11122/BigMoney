**为什么做这一件**

`robust_tsmom_commodity` 的 `120d`/`250d` 两臂与 `census_commodity` 的 `tsmom|{lookback:120,skip:21}|ls`

风险两项都比它自己选中的臂更好，而读者从来没有被告知它们存在。

**自检钉住的行为腿（不是描述）**
1. 跨卡同数字 + 同面板 → 并成一条；且臂名不同也照并（按测量不按名字）
2. 同一张卡两条活臂不同数字 → 保持两条（不误并）
3. 同数字但 bar 数不同 → **不**并（面板是身份的一部分）
4. 夏普**和**回撤同时更好 → 标记；只赢一项 → 不标记（保守读法）
5. 被标记的臂必须说出它赢了哪条活臂、自己的差值、以及卡片自己 `criteria` 里的那道门
6. 缺数字的活臂 → 保留可见，不许被并掉或读成 0
7. 读不懂的判词词面（`BASELINE_REFERENCE` 等 4 个）→ 原样列出，不猜
8. 卡级活口（无 `arms[]` 的 `basis_timing_size` / `basis_timing_perm`）→ 必须成行，否则分母少算
9. 卡级 `NO_EDGE` → 不计入活口
10. `build` 确定性：同输入两次 → 除 `generated` 外逐字段相同

**两枚自捕（均已修）**
1. 首版 `collect_cards()` 只收「有 `arms[]`」的卡 → `basis_timing_size` / `basis_timing_perm` 两张活卡
   被静默丢掉，distinct 读数从 4 掉成 2。这正是本件要审计的那个病，被自己犯了一遍。
2. 首版对「被扔掉的臂」用 `min(sharpe)` 挑对比对象 → 拿最弱的那条活臂比，结论偏软；
   改为 `max(sharpe)`（跟**最强的**活臂比），差值随之变严（250d long 的 Δ回撤 +8.04pp → +5.18pp）。

**未验证（如实）**
- 去重靠「面板 + 三个数逐位相同」：同一规则跑在两个略有差别的面板上会被算成两条；
  两条不同规则碰巧同三数会被并成一条。本册里前者更可能（重复组带着同一份 bar 数）
- 只读各卡自己的 `arms[].common_window` / `criteria` / `products`，不重算任何收益、不重判任何门
- 「被扔掉的臂」不是推荐：多空 vs 只做多的敞口口径不同，样本外一致性也没查（120d long OOS 9.3 vs ls 9.44；
  250d long 8.51 vs ls 7.90——一赢一输），要变成推荐是另开票的事
- 只覆盖 `results/bench_*.json` 里有 `arms[]` 或顶层 `verdict` 的卡；r2137–r2139 的 carry / 资金面不在册内
