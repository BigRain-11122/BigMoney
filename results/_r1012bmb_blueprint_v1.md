## 一、游戏线范式拆解（移植母本·六件内核）
①**轮式循环**（拉取→挂账盘点→自领活→执行→簿记→上链→自续）②**活性门控预算**（iteration_loop v2：连续 25min 零输出静音门+240min 硬顶·持续流输出长轮永不误杀）③**自愈 runner**（服务器死→自动重启→resume 续烧→到齐自停）④**自领活引擎**（队列空+GPU 闲→自动领下一条）⑤**台账自簿记**（orders/LEDGER 自动落账+反转闸+原子推）⑥**S4U 注册**（零黑窗律）。

## 三、CONTENT-LOOP v1 规格（内容线 OS 循环）
1. **循环骨架**：每 20-30min 一轮·寄宿各机既有 iteration_loop 框架（S4U·零新进程族）——步序=fetch→挂账盘点（各线 QUEUE.md）→自领活（按车道+五件套闸可用性）→执行单站→簿记（LEDGER/orders 自动行+反转闸）→上链→自续。
2. **三工位+双审 agent 化**：①调研位（radar C 查+受众之声采集→入研发队列）②生成位（KF/i2v/TTS 批量 runner 复用）③剪辑位（剪辑语法表程序化执行+装配链自动跑）④审看位=盲评 agent（≥9 放行）+制监席 agent 独立对抗审查（双签 agent 化·**独立席不撤·禁自审自签**）。
3. **闸在环内不降级**：五件套全保留——环节签认=该站 agent 过自检单；**版本数 ≤3=队列状态机强制**（第 3 版前自动根因停线+落闸复盘行）；日进化班=循环末班自动盘点好/坏。
4. **车道分机**：bm-b=漫剧/短剧/短视频主循环宿主（声音+轻视频车道）·bm-c=生成视觉 GPU 批量（承接生成位工单）·bm-a=装配/终审聚合+周末循环班（工作日白天让路律不变）。
5. **三不自动化（红线）**：①发布动作=候 CEO 终审（零卡点令终点不变）②账号写操作=物理件域（凭据未到=该站自动暂停不卡环）③五件套闸降级=禁（自动化提效不降质·制监席回扫专查项）。

## 五、定位律（CEO 令 20:22·参考游戏但要高于游戏）
1. **适合业务发展（第一律）**：循环的形状由业务定——排产跟着**业务优先级**（MV 41 曲线 P0/漫剧 P0/新线立项）与**受众节奏**（热点窗口/发布窗口/日更档）走；每轮自领活前自检**「这一站推进哪条业务的哪个指标」**——答不出的活不进环；纯技术自嗨件禁排产（radar §六 收益导向四段制接入：研究→接线→执行→收益）。
2. **高于游戏四维（内容线独有·游戏环没有的）**：
   - **创作质量闸在环内**：五件套+创作高压线（俗/烂一票否决）+双签 agent——游戏环只有工程 QC，内容环每轮过**创作审判**；
   - **受众反馈闭环**：热点雷达+受众之声+上头度数据 → 日进化班 → 回灌排产（内容=受众即时可见·游戏无此面）；
   - **资产复用经济**：自有角色库（面孔/声音）+正典 playbook+风格资产全条线复用 → 边际成本递减（每品资产复用率入成本账）；
   - **日进化+跨线回灌**：判例当日跨线共享（游戏线按周/月迭代·内容线按日）。
3. **验收口径升级**：10-28 周审判据在 §四 原三件（72h 无人值守 ≥3 站/日·缺陷率不升·台账零断账）之上加**业务面三行**——推进的业务指标清单+资产复用率+受众面数据（上头度代理指标）。
