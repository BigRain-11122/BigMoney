ROOT CAUSES (two, different)
----------------------------
1. printer: both legs print quoted page lines; a GBK console cannot encode U+00A5.
   The chain reads the traceback exit code as a page verdict, so a printer bug
   wore the label of a page defect for as long as the leg has been red.
   fix: sys.stdout.reconfigure(errors="replace") in main() (keeps the console's
   own encoding, only stops it from raising).
2. coverage: live_usage_day_words had 23 claim rules for 40 printed dates. The 19
   it could not read are exactly the sentences r1779/r1787 added to the page
   (ticket provenance, withdrawal decision, today's-action swap block, carry
   provenance, basis-timing in-band line). A face that can never be green is the
   r1789 permanent-red family.
   fix: 14 rules, each bound to a field that already exists on the page JSON.
   A date that rides inside a file name (TICKET-2026-11-17.json) is an
   identifier, not a claim -> _unmapped_classifier buckets it and the count is
   printed as DATE-BUCKETS; it never joins the ok count.
